# Поиск музыки, станции и обложки

## Что было найдено

1. «Музыка офлайн» искала только в интернете. Скачанное было разбросано по плейлистам, а без сети раздел предлагал уйти в другой раздел вместо поиска локальных файлов.
2. Radio Browser объединял основной запрос и транслитерацию, а следующую страницу запрашивал со смещением `items.length`. После объединения и удаления дублей это число не совпадало с размером страницы источника: результаты пропускались или повторялись.
3. Успешный поздний ответ SomaFM не проверял отмену. После переключения источника он мог заменить актуальную выдачу. Изменение локального фильтра SomaFM также повторно запускало загрузку и очищало список.
4. Смена источника музыки сбрасывала выдачу, а повтор после ошибки второй страницы начинал поиск заново с первой. Если все элементы страницы отфильтрованы, кнопка дальнейшей загрузки могла исчезнуть, хотя у источника оставались страницы.
5. `Cover` бессрочно запоминал URL после любой сетевой ошибки и отбрасывал изображения меньше 48 px, включая настоящие логотипы 32×32. В отдельных местах legacy HTTP-картинки терялись до рендера.
6. Обложка плейлиста не передавалась трекам без собственной картинки при воспроизведении и восстановлении очереди. Импорт локального MP3 извлекал текстовые ID3-теги, но не APIC/PIC и не сохранял название альбома.
7. Загрузчик принимал HTML/JSON вместо аудио и пустые ответы как скачанные файлы. Все ошибки загрузки ошибочно объяснялись CORS. Сверка Cache API могла удалить ещё индексируемый импорт/загрузку как «неучтённый файл».

## Новая офлайн-фонотека

**Обзор → Музыка офлайн → На устройстве.** Рядом остаётся **Найти музыку** — существующие Internet Archive, Openverse и Wikimedia Commons с их лицензиями и ограничениями.

- Общая выдача скачанных VOD из каталога, треков всех плейлистов и импортированных файлов.
- Наличие подтверждается офлайн-индексом и сверкой с Cache API, а не только флагом `local`. Потерянные файлы не выдаются за доступные.
- Одинаковый URL в нескольких плейлистах показывается один раз; названия всех связанных плейлистов участвуют в поиске.
- Поиск по отдельным словам в названии, исполнителе, альбоме, жанре и имени плейлиста. Регистр, пунктуация, ё/е и диакритика не мешают; точное название и начало названия имеют приоритет.
- Фильтры «Всё / Скачанное / Свои файлы», сортировка по дате загрузки, названию и исполнителю.
- «Слушать найденное» и перемешивание создают очередь из отфильтрованного набора, не всей коллекции. Рендер первых 80 строк ограничивает нагрузку; «Показать ещё» не ограничивает очередь.
- Из строки можно открыть исходный плейлист. Файлы добавляются прямо здесь, доступен прогресс фоновых загрузок.
- Поисковый запрос в интернет-разделе сохраняется при переходах между двумя режимами. Последний режим хранится на устройстве; при потере сети автоматически показывается локальная фонотека.

## Поиск станций и музыки

`searchStationsPage` возвращает `items`, `nextOffset`, `hasMore`. Смещение относится к необработанным страницам каждого варианта запроса; наличие следующей страницы определяется до фильтрации и дедупликации. Разный регистр пути в URL больше не считается одним потоком. Прежний `searchStations` остаётся совместимой обёрткой, возвращающей массив.

UI не принимает отменённые/устаревшие ответы. SomaFM фильтруется без повторной загрузки списка. Enter применяет запрос немедленно; при вводе остаётся debounce. Повтор ошибки продолжает именно неудавшуюся страницу.

Смена источника музыки повторяет уже отправленный текстовый запрос в новом источнике. Черновик нового запроса явно отличается от показанной выдачи. Очистка отменяет запрос, а «Показать ещё» доступно даже после пустой отфильтрованной страницы.

## Обложки

- Единая `artworkUrl`: HTTPS, legacy HTTP с повышением до HTTPS и реальные встроенные data-картинки. Небезопасные схемы, URL с учётными данными и известные waveform-заглушки отбрасываются.
- Нет глобального бессрочного чёрного списка. Сетевая ошибка локальна для изображения; восстановление сети/возврат к видимой вкладке позволяет повторить загрузку. Изменение URL не наследует состояние предыдущей картинки.
- Маленький корректный логотип отображается; отклоняются только сломанные/пиксельные изображения и распознанные музыкальные waveform-заглушки. Радиологотипы не прогоняются через эвристику waveform для музыки.
- Обложка плейлиста/подписки используется, когда у трека нет своей, в списке, плеере, очереди после reload и новой офлайн-фонотеке.
- Для импортируемых MP3 читаются JPEG/PNG из ID3 APIC/PIC с предпочтением front cover. Чтение ограничено 4 МБ, картинка уменьшается до 640 px и хранится локально как data URL. Неподдерживаемая/повреждённая картинка не мешает импорту аудио. Альбом сохраняется в `PlaylistItem.album` и проходит нормализацию/импорт резервной копии.
- Если настоящей картинки нет, музыка получает музыкальную иконку, а станция — инициалы. Случайная или чужая «обложка» не подставляется. Извлечение картинок FLAC/MP4 и зашифрованных/сжатых/unsynchronized ID3-фреймов в эту работу не входит.

## Надёжность скачивания

HTML, JSON/XML и пустые файлы не индексируются как аудио. Ошибка отображает фактическую причину вместо безусловного объяснения CORS. Перед повторной загрузкой проверяется, остался ли файл в Cache API.

Cache.put и IndexedDB не атомарны: активные записи учитываются по профилю/ID, очистка пропускает их и повторно читает индекс для недавно завершённых загрузок. Запись кэша использует исходный профиль и не дописывает индекс в другой аккаунт после его переключения.

## Дизайн и проверки

`music-search.css` наследует палитры/шрифты всех восьми интерфейсов. На телефоне сокращены вводные блоки, источники занимают полную ширину, фильтры станций расположены в две колонки, основные действия имеют удобную область нажатия. Проверены 320 / 390 / 768 / 1440 px, включая 320 px при 125%.

`tests/search-library.spec.ts` добавляет 19 сценариев: офлайн-поиск/очередь/настоящий Cache API, путь поиск → скачивание → офлайн, импорт MP3 с картинкой/альбомом, пагинация/дубликаты/транслит, запоздавший SomaFM, повтор страницы, смена источника, восстановление обложек, все восемь дизайнов, потерянные файлы, неправильные ответы вместо аудио и параллельная сверка записи кэша.

Production smoke: 320, 390 и 1440 px, все восемь интерфейсов, импорт WAV, поиск/скачивание из тестового ответа провайдера и воспроизведение при отключённой сети. Отдельно без моков проверены настоящий Service Worker, повторный запуск страницы без сети и воспроизведение импортированного WAV. Ошибок страницы в этих сценариях нет. Живые запросы к Radio Browser через proxy, Internet Archive, Openverse, Wikimedia Commons, SomaFM и Radio Garden через proxy вернули HTTP 200 и результаты; это проверка доступности на момент запуска, не гарантия всех потоков/файлов.

Команды: `npm run typecheck`, `npm run build`, `npm test`. Автоматизация — Chromium; физические устройства и Safari отдельно не проверялись.

Финальная проверка: **154 теста прошли одним полным прогоном** (Chromium), `npm run typecheck` и `npm run build` прошли.
