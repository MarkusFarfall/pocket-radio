# Полная синхронизация аккаунта

Войдите на другом компьютере — и там появятся станции, плейлисты (вместе с обложкой, которую вы
поставили сами), прогресс прослушивания, история для статистики и выбранное оформление. Скачанные
аудиофайлы остаются на своём устройстве: в облако уходят только метаданные, поэтому на новом
компьютере музыку нужно скачать заново.

## Что переносится

| Данные | Документ в облаке | Примечание |
| --- | --- | --- |
| Станции, избранное, заметки | `station:<syncId>` | сопоставление по `syncId`, затем по URL; проверка доступности (`health`) остаётся на устройстве |
| Плейлисты | `playlist:<id>` | весь плейлист, включая **свою обложку** (`data:`-изображение) и треки |
| Прогресс треков и подкастов | `progress:pp:<key>` | побеждает более свежая позиция |
| Сохранённые треки | `track:<название>:<исполнитель>` | ключ нормализован: регистр, «ё», пробелы |
| Статистика | `session:<syncId>`, `event:<hash>` | сессии объединяются по `syncId`, записи удалённых станций сохраняются |
| Оформление и настройки | `pref:<имя>` | интерфейс, тема, плеер, плотность, ЭК, поведение офлайн, стартовый раздел, режим ПК |

Громкость, скорость воспроизведения, «не гасить экран» и скачанные файлы не синхронизируются: это
свойства конкретного устройства.

## Как это работает

- Каждая сущность — отдельная строка `public.sync_docs`. Старый способ хранил весь профиль одной
  JSON-записью в `user_data`; с обложками и статистикой такая запись упирается в лимит размера
  запроса REST, а удаления и частичный обмен в ней не выразить.
- Изменения замечаются на уровне хранилища (`syncBus`): `setSetting`, сохранение станции, запись
  сессии, скачивание файла и т.п. помечают документ, движок объединяет пометки и отправляет пачками
  с задержкой ~2 секунды.
- Отпечаток (`hashDoc`) каждой синхронизированной версии хранится локально в `syncMeta`. Поэтому
  повторно уходят только реальные изменения, а встречная копия не затирает несохранённые правки.
- Удаления передаются «надгробиями» (`deleted: true`): удалили плейлист на одном устройстве — он
  исчезнет и на другом.
- Время изменения ставит сервер (триггер `sync_docs_touch`), поэтому расхождение часов устройств не
  ломает порядок.
- Первое подключение нового устройства не удаляет его локальные данные: облако применяется как
  дополнение, а удаления — только для записей, которые в облаке действительно были.

## Требования к серверу

Один раз выполнить `supabase/schema.sql` в Supabase → SQL Editor. Для уже работающего проекта нужен
фрагмент из раздела 3b: таблица `sync_docs`, триггер `updated_at` и RLS. Приложение определяет, что
таблицы ещё нет, и показывает готовый SQL в Настройки → Аккаунт → «Подготовить сервер» с кнопкой
«Скопировать SQL».

## Ограничения

- Скачанные аудиофайлы в облако не попадают: бесплатный Supabase даёт 1 ГБ, а музыка из
  плейлистов быстро его съедает. На новом устройстве треки доступны по ссылке, их нужно скачать
  заново — кнопка скачивания в плейлисте.
- Синхронизация идёт, пока приложение открыто; при возврате на вкладку и восстановлении сети —
  сразу, иначе каждые несколько секунд. Ручной запуск — кнопка «Синхронизировать сейчас».
- Старый снимок `user_data` остаётся: он один раз импортируется при переходе на документы и доступен
  как ручная резервная копия, пока таблица `sync_docs` не создана.

## Файлы

| Файл | Назначение |
| --- | --- |
| `src/lib/sync.ts` | движок: цикл обмена, очередь, состояние для интерфейса |
| `src/lib/syncDocs.ts` | сборка документов из базы и применение облачных документов |
| `src/lib/syncKeys.ts` | ключи документов, нормализация, хеши |
| `src/lib/syncBus.ts` | сигналы об изменениях из слоя данных |
| `src/lib/syncPrefs.ts` | перенос оформления и настроек через настоящие сеттеры |
| `src/lib/cloud.ts` | REST Supabase без SDK, коды ошибок |
| `src/views/settings/CloudSync.tsx` | блок «Облако» в настройках |

## Тесты

- `tests/cloud-sync.spec.ts` — полный цикл на подменённом Supabase: отправка станции, плейлиста со
  своей обложкой, сессии и оформления; восстановление на «другом компьютере»; удаления в обе стороны.
- `tests/sync-utils.spec.ts` — хеши и ключи, сборка документов, обратимость настроек, отказ от
  некорректных значений.
- `tests/import-sync.spec.ts` — прежний импорт JSON и ручная резервная копия `user_data`.
