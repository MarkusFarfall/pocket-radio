# Плеер как часть выбранного интерфейса

**Настройки → Оформление → Стиль** меняет всё приложение, включая плеер. Семь неклассических интерфейсов больше не назначают один из шести независимых старых скинов.

| Интерфейс | Полноэкранная композиция |
| --- | --- |
| Панорама | Крупная обложка и воздушная зона названия/управления, очередь снизу |
| Фокус | Компактная обложка рядом с названием, центрированные органы управления и отдельный список очереди |
| Ателье | Альбомный разворот с обложкой-конвертом, отдельная полоса воспроизведения; без виниловой деки |
| Ноктюрн | Спокойная тёмная сцена, обложка и название, нижний округлый остров управления; без неона |
| Редакция | Типографический разворот, крупный заголовок, обложка справа, линейки и прямые кнопки |
| Медиатека | Зона прослушивания с обложкой и отдельная панель очереди справа |
| Пульт | Рабочие модули: текущий трек, управление и очередь |

На телефоне композиции перестраиваются в одну колонку. Мини-плеер и настольный dock наследуют ту же палитру и типографику; разные формы обложек/кнопок согласованы с интерфейсом. У Фокуса компактная горизонтальная полоса управления. Обложки в связанных плеерах не вращаются.

## Приоритет и сохранение

- `useAppDesign()` определяет интерфейс полноэкранного плеера, mini и dock. Старые сохранённые `pr.playerAppearance` не могут подмешать винил/кассетник/чужую палитру к неклассическому интерфейсу.
- Новых настроек или миграции пользовательских данных нет. Уже выбранные раньше интерфейсы начинают использовать соответствующий плеер автоматически.
- Плеер наследует `--bg`, `--surface`, `--surface-2`, `--line`, `--ink`, `--muted`, `--accent`, `--accent-ink`, `--ui-font`, `--ui-display`. Ручная смена палитры/шрифта применяется и здесь; CSS связанных плееров не задаёт собственные палитры.
- Классика сохраняет шесть независимых шаблонов, их композиции и настройки анимации. Существующий снимок настроек Классики восстанавливается при возврате. Переключение глобального интерфейса больше не перезаписывает `playerAppearance` случайным старым шаблоном.
- В **Оформление → Плеер** неклассического интерфейса показан его связанный плеер, переключатель телефон/компьютер и объяснение. Отдельные шаблоны открываются явным действием «Перейти в Классику для отдельного плеера».

## Реализация

- `AppPlayerExperience.tsx` — только композиция; принимает прежние `PlayerExperienceSlots`.
- `PlayerUI.tsx` — те же живые обработчики воспроизведения, перемотки, громкости, избранного, добавления в плейлист, EQ, очереди и возврата к источнику. Новый аудиодвижок не создаётся.
- `AppPlayerPreview.tsx` — инертная миниатюра того же `AppPlayerExperience`, масштабируемая через ResizeObserver. Данные явно демонстрационные; интерактивные элементы не попадают в Tab-порядок.
- `app-player.css` — адаптивные связанные композиции и компактные плееры. Подключается после глобальных интерфейсов. Независимые `.player-skin-*` отсутствуют на связанных плеерах.
- `AppDesignTemplate.player` удалён: соответствие определяется идентичностью приложения, а не сопоставлением старых скинов.

## Проверки

`tests/app-player.spec.ts` добавляет восемь сценариев:

- все семь вариантов на 320 / 390 / 768 / 1440 px, в том числе 320 px при масштабе 125% и уменьшении анимаций;
- наследование всех токенов, отсутствие чужих скинов и горизонтального обрезания органов управления;
- переключение уже открытого плеера без остановки WAV-воспроизведения, сброса позиции, очереди и контекста;
- реальные пауза/возобновление, открытие EQ, громкость, избранное, выбор следующего трека и возврат к реальному плейлисту на телефоне и компьютере;
- настройки с соответствующим предпросмотром в обоих размерах, перезагрузка и восстановление независимого винила в Классике;
- старое сохранённое сочетание Ателье + винил автоматически показывает Ателье; смена палитры и шрифта наследуется без сброса.

Существующие проверки Классики и шести независимых шаблонов остаются включены. Команды: `npm run typecheck`, `npm run build`, `npm test`. Браузер автоматизации — Chromium; физические устройства и Safari отдельно не проверялись.

Проверка этой реализации: typecheck и production build прошли; полный набор — **135 тестов**. Дополнительно production-сборка проверена на 390 и 1440 px через реальные UI-переходы по семи интерфейсам, локальный WAV, очередь из трёх треков, паузу/возобновление, изменение пресета EQ, возврат к исходному плейлисту и перезагрузку. Ошибок страницы в этих сценариях нет.
